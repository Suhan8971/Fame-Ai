# --- Render start command ----------------------------------------------
#   gunicorn app:app --workers 1 --threads 8 --bind 0.0.0.0:$PORT --timeout 120
#
# --workers 1 is NOT a suggestion: the scan session (state dict, the
# current browser-uploaded frame, the camera thread) lives in this one
# process's memory, not in a database. Multiple gunicorn workers would each
# get their own independent copy, so a /status poll could land on a
# different worker than the one /start or /push_frame hit and see stale or
# empty state. --threads 8 is what lets that single worker still handle
# concurrent requests (status polling, frame uploads, etc. at once),
# mirroring the threaded=True already used by `python app.py` locally.
# Do NOT add --preload: it would import this module (and construct the
# try-on worker's OS process) once in gunicorn's master before forking,
# which the fork would then duplicate rather than share.
